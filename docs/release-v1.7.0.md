# Guyue v1.7.0 Release

Date: 2026-07-29
State: `released`
Base tag: `v1.6.0`

## Purpose

v1.7.0 strengthens Guyue's ability to learn without losing control. It adds a direction firewall for high-impact ideas, makes multi-turn plan drift resettable, and reduces the high-risk cognitive-expansion contract to a smaller evidence spine that can still be checked mechanically and independently.

## What Changed

- High-impact designs now begin with an unsolved problem, observed failure, native baseline, no-change and repair alternatives, falsifier, blast radius and rollback. A popular solution name or user agreement is not adoption evidence.
- Material plan reshaping across multiple turns clears inherited confidence instead of endlessly optimizing the original direction.
- External skills and methods remain untrusted candidates until their reusable value, overlap, maturity, placement, subtraction and regression impact are proven.
- Explicit read-only analysis proceeds in one bounded pass without redundant confirmation. Network access, paid actions, delegation, writes and cross-budget expansion still require the corresponding boundary.
- `cognitive-expansion` high-risk output now uses eight ordered sections instead of a large general ledger. It keeps source identity exact, distinguishes competing causal mechanisms from missing evidence, records one highest-value next item, and treats the runtime receipt as the final budget fact.
- Live evidence and output-quality runners now support an explicit Codex binary, bounded timeout diagnostics and reusable hash-matched producer artifacts. The live runner and strict checker share a regression-tested routing hash surface.

## Boundaries

- One successful runtime/model matrix does not prove arbitrary inputs, other runtimes, real-user value or long-term outcomes.
- Model memory may propose candidates but cannot become source evidence. Current, disputed, regulated or version-sensitive claims still require bounded source work.
- No autonomous browsing, scheduled self-modification, automatic candidate promotion or external installation loop is enabled.
- Release metadata changes do not retroactively upgrade old evidence; the release lock binds the exact published payload.

## Next Entry Points

- Add new holdouts only when they test a genuinely new failure mode; do not recycle contaminated samples to manufacture confidence.
- Expand to another runtime only when the comparison will change an adoption or compatibility decision.
- Prefer subtractive improvements to new root-level machinery, and retire controls that no longer prevent a demonstrated failure.
