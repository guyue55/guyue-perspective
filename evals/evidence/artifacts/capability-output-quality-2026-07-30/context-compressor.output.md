每轮上下文包固定为：

1. 任务目标、用户约束、当前决策和未决风险。
2. 日志摘要或定点窗口，保留原始日志文件与行号范围。
3. 已激活 Skill 的必要规则与 `skills/<name>/SKILL.md` 路径。
4. 已选 MCP 工具的最小参数 schema。
5. 上轮检查点：已确认事实、已排除路径、下一步、证据指针。

原始内容不以摘要替代事实源。摘要中必须保留可回查标识，例如：

- `logs/<session>.log:L120-L168`
- `skills/<name>/SKILL.md`
- `mcp:<server>/<tool>@<schema-version-or-hash>`

若运行环境无法支持 MCP schema 的懒加载，需要先在工具注册层提供“能力索引 + 单工具 schema 展开”机制；否则 Agent 侧无法阻止 80 份 schema 被预注入。

度量采用同一组代表性任务做压缩前后对照，并使用实际部署模型的 tokenizer 或 API usage 字段：

\[

\]

\[

\[

每轮记录以下字段：

| 指标 | 口径 |
|---|---|
| 输入 Token | 分别记录日志、Skill、schema、任务包，避免只报总数。 |
| 节省 Token / 节省率 | 以上述公式计算；未通过 tokenizer/API usage 复算时标为“预估”。 |

| 延迟 | 相同任务的端到端耗时，中位数与 P95。 |

验收门槛：

- 压缩后每项结论都可回查到原始日志、Skill 或 schema。
- 对照任务的完成质量不低于全量上下文基线，且无关键风险漏检。

- 未实测前，只能称“预计节省”，不能承诺具体比例。
