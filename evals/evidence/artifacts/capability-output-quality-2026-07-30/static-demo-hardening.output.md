按本次已确认前提，范围仅为 `Demo/index.html` 的静态报告面：不引入后端、框架或在线依赖。当前工作区未独立定位该文件及其现有导出库，以下为可直接实施的加固工作包，不宣称已修改或验证。

## 加固目标

导出按钮只能表达已发生的真实事件：

| 情况 | 页面反馈 | 禁止反馈 |
|---|---|---|
| 导出依赖缺失 | 显示报告内的离线导出教程回退 | “导出成功”“下载完成” |
| 报告尚未渲染完成 | “报告准备中，暂不能导出” | 发起空白或残缺导出 |
| 导出过程抛错 | “未生成文件，可重试或使用浏览器打印” | 成功 toast |
| 浏览器打印被请求 | “已请求浏览器打印，请选择‘另存为 PDF’” | “PDF 已生成” |
| 文件下载触发 | “已发起下载” | “文件已保存” |

## 最小静态改动

1. 将现有导出点击逻辑收敛为一个入口，例如 `runReportExport()`；开始时清除任何成功提示并进入忙碌态，避免双击。

2. 先等待报告状态稳定，再检查当前导出路径所需的函数和本地资源。依赖名称沿用页面既有实现；不要臆造或新增 PDF 库。

```js
async function runReportExport() {
  clearExportSuccess();
  setExportBusy(true);

  try {
    const ready = await prepareReportForExport();
    if (!ready) {
      showExportError('报告仍在准备中，尚未生成文件。');
      return;
    }

    const missing = getMissingExportDependencies();
    if (missing.length) {
      showOfflineExportTutorial({ missing });
      return;
    }

    await exportReportArtifact();
    showExportInitiated();
  } catch (error) {
    showExportError('导出未完成，未生成文件。可重试或使用浏览器打印。');
  } finally {
    setExportBusy(false);
  }
}
```

3. 依赖缺失时，在报告导出控件附近显示可见回退卡片或对话框，不使用短暂 toast：

> **当前离线演示未加载报告导出组件**  
> 未生成 PDF 或下载文件。请在浏览器中打开完整报告，选择“打印”→“另存为 PDF”。

- `打开浏览器打印`：仅调用 `window.print()`；调用后提示“已请求浏览器打印”，不称 PDF 已生成。
- `再次检查导出组件`：重新执行依赖预检。
- 教程内容内置于页面并使用本地样式/资源；没有已确认的官方链接时，不添加第三方视频或外链。

4. 若页面使用浏览器原生打印作为正式 PDF 路径，明确把它定义为“打印/另存为 PDF”，而非“PDF 导出服务”。`@media print` 中隐藏 sticky 导出控件、教程卡片和非报告区域，确保完整报告可打印且不被控件遮挡。

5. 保持回退组件可访问：错误区使用 `role="alert"`/`aria-live`，对话框获得焦点并支持关闭；移动端以报告内嵌卡片呈现，避免被固定按钮遮挡。

## 验收矩阵

- 删除或模拟缺失导出依赖：点击导出后显示教程卡片；不下载、不弹成功提示。
- 报告未稳定：不进入导出，不显示成功。
- 导出函数异常：明确显示“未生成文件”，可重试。
- 依赖完整且导出函数完成：仅显示“已发起下载”；检查下载内容包含完整报告。
- `file://`、断网和移动宽度：教程无需网络或 iframe，操作入口始终可见。
- 打印预览：非报告控件隐藏，长报告不截断、不遮挡。

实施前唯一需要补齐的是现有导出依赖、报告容器和教程入口的实际选择器；这只影响绑定位置，不影响上述失败状态和文案边界。
