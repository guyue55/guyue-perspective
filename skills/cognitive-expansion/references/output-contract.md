# 输出合同卡

本卡只用于专业地图和高风险交接。目标是形成短、可审计、能安全交给专业角色继续工作的认知地图，不用复杂编号和字段迷宫表演“全面”。

微量与轻量模式不加载本卡。高风险场景必须守住真实性、来源身份、预算、专业批准和不可直接实施边界；格式只检查会改变这些边界的内容。

## 固定交付顺序

专业或高风险终稿使用以下八个 H2，顺序固定：

1. `## PRE-EVIDENCE-SNAPSHOT E0`
2. `## B0 PRE-TOOL 预算账本`
3. `## 问题地图`
4. `## 证据边界`
5. `## 竞争解释与遗漏`
6. `## 专业交接`
7. `## 下一证据`
8. `## B1 FINAL 与停止`

E0 与 B0 必须是前两个业务语义区块。运行时入口、目标 Skill 和本控制卡属于控制面读取；在 B0 冻结前不得读取用户未提供的业务材料、外部来源、相邻业务 Skill 或执行联网。

## E0：保留取证前认识

E0 至少写清：

- 用户原始框架；
- 用户给出的已给事实；
- 模型新增的候选/假设；
- 会改变决定的冲突；
- 当前未知。

`已给事实` 只证明用户输入如此写，不等于来源已核验。不要把模型常识、供应商宣传、搜索摘要或不可恢复片段写成已核事实。
字段必须语义可识别，但无需机械复读“用户”前缀；例如 `原始框架：` 与 `用户原始框架：` 等价。

## B0/B1：预算由运行器约束

B0 使用固定六列：

`资源｜硬上限｜起始消耗｜安全预留｜状态｜测量依据`

B1 使用固定五列：

`资源｜硬上限｜实际或代理消耗｜状态｜测量依据`

本卡中的全角 `｜` 只用于行内描述列名。所有正式表格必须使用 ASCII `|` 分隔真实 Markdown 单元格，并给出同列数的 `---` 分隔行；禁止输出单列的 `| 资源｜硬上限｜... |`。

两张表都列：

- 最大轮数；
- 墙钟时间；
- 近似有效 Token；
- 只读工具调用；
- 材料打开；
- 可见输出；
- 授权子任务；
- 付费成本。

同一目标的生产、复审、修正和子任务共享任务级总账 `BΣ`。B0 表后必须单独写一行 `BΣ：` 及任务级总上限；默认最多一次自动实质修正，第二次及以后需要用户继续授权。额度、暂时不可用或超时不会自动续杯。

生产模型看不到任务结束后才生成的运行器收据。B1 中未能直接测量的数值必须写成 `模型侧代理，运行器收据待补` 或同义限定，不能冒充最终事实；代理与收据不相等本身不是失败。运行器收据才是最终用量事实：有缓存时，有效 Token 为 `max(input-cached, 0)+output`；可见输出使用完整产物的 `max(Unicode 字符数, UTF-8 字节数÷2)` 保守代理。运行器在产物外复核收据，任一硬上限越界即失败并返回 `CE-BUDGET-EXHAUSTED`，不能靠自报较小数字放行。

## 问题地图：只保留改变决定的视角

使用固定五列：

`视角｜状态与依据｜对决定的影响｜关键未知｜下一证据`

规则：

- 保留 3–6 个会改变采购、部署、批准、验收或停止决定的视角；
- 每行只用 `已给事实`、`候选/假设`、`未知`、`冲突`、`来源主张`、`有界推断` 或 `价值/决定`；
- 每行说明为什么会改变决定，不用通用 PESTLE/SWOT 清单凑数；
- 未知必须有一个可执行下一证据；
- 不因高风险而追求长篇，优先保留失效、安全、实际获益、运营容量/成本和遗漏边界。

`来源主张` 只允许用于具备可恢复材料身份的内容；证据边界认定材料身份不可恢复时，问题地图必须改用 `已给事实`、`候选/假设`、`未知` 或 `冲突`，不得出现 `来源主张`。

## 证据边界：材料身份先于引用

必须逐字说明：`给定片段不是已核来源`。

只有具备可恢复材料身份、版本或日期、正文支持位置的材料，才可登记来源主张。题面给出的材料类型只能写成“用户标注为……”；不得自行补充匿名、官方、内部、独立或具体机构等来源元数据。搜索摘要、供应商宣传片段、访谈摘录和用户转述只能作为：

- 已给事实；
- 候选线索；
- 未知或冲突。

不可恢复材料不授 `S/E`。可以用“不授予任何 S/E”等同义表达，但必须同时写清材料身份不可恢复且未授级。用户禁止联网时不得尝试补齐；写明本轮 `联网=禁止且未使用`。没有可靠来源时返回 `CE-EVIDENCE-GAP`，不把来源缺口包装成“部分核实”。

## 竞争解释与遗漏：至少各一项

使用固定五列：

`对象｜主解释｜竞争解释或遗漏机制｜可区分证据｜结果如何改变地图`

至少包含：

- 一个与主解释不同的竞争机制，以及能区分两者的同对象证据；
- 一个被当前观察框漏掉的人群、环境、阶段或失效条件，以及漏捕会造成的后果。

固定表头已经声明第三列的语义，行内可以直接写另一可能机制或遗漏机制，不要求重复“竞争解释”四字。
竞争机制必须解释同一观察结果的另一条因果链；`未知`、`未记录`、`未证明`、证据不足或“主解释可能失败”只是证据状态，不算竞争机制。可区分证据必须能在同一对象或事件上区分两条机制。

证据不足时结果保持未知，不凭模型偏好给某个解释升权。

## 专业交接：高风险不得自批

高风险交接至少覆盖三个独立责任域：

1. 效果或有效性识别；
2. 运营容量与成本；
3. 安全、权利或法域遗漏。

使用固定五列：

`责任域｜具体专业角色｜待交付的版本化工件｜可观察通过条件｜当前状态`

规则：

- 角色必须具体，不能只写“专家”；
- 工件写名称和版本规则，例如 `验收方案-v待定`，未知版本不得伪造日期或 hash；
- 通过条件必须可观察；阈值未知就明确由谁制定，不能编造数字；
- `当前状态` 未闭合时写 `CE-PROFESSIONAL-REVIEW`；
- 专业复核、采购批准和最终实施授权必须分开。

## 下一证据：只选一个

写一条：

`最高价值下一项：<工件或材料>｜所有者：<具体角色>｜选择依据：<它会先改变哪个决定>`

不得把多个请求打包成“下一项”。如果一个缺失输入会改变整个地图，优先该输入；否则选择最能区分竞争解释或关闭最高后果未知的证据。

## B1 与停止

停止区必须逐字包含：

- `地图状态：有界可用` 或 `地图状态：未完成`；
- `决策就绪：`，并列出适用的 `CE-...`；
- `证据边界：`；
- `重新开启条件：`；
- 高风险未就绪时写 `不得据此直接实施`。

这些字段使用项目符号或独立段落呈现，不得用行尾空格制造 Markdown 硬换行。

失败代码：

- `CE-INPUT-GAP`：缺少会改变方向的输入；
- `CE-EVIDENCE-GAP`：关键主张没有相称来源或数据；
- `CE-CONFLICT-UNRESOLVED`：竞争解释当前无法区分；
- `CE-BUDGET-EXHAUSTED`：运行器收据或完整产物代理越界；
- `CE-AUTHORIZATION-REQUIRED`：下一动作缺少具体授权；
- `CE-PROFESSIONAL-REVIEW`：高风险用途缺少合格专业复核。

地图有用不等于决定可执行。任何来源身份、预算、专业复核或授权门未闭合，都必须停止在交接层。
